## 1. 5문항 출제 통계 (5,000회 대규모 시뮬레이션)

현실적인 수험생 데이터 분포(NEW 500개, WEAK 50개, DUE 30개, GENERAL 200개, MASTERED 120개)를 기반으로 **5,000회 연속 5문항 퀵 퀴즈 selection 시뮬레이션(총 25,000문항)**을 실행한 전수 측정 결과입니다:

```text
======================================================
📊 [5,000회 시뮬레이션 통계 결과]
- NEW 평균:      3.00개 / 5 (60.0%)
- WEAK 평균:     2.00개 / 5 (40.0%)
- DUE 평균:      0.00개 / 5 (0.0%)  (WEAK 슬롯 소진 후 우선 배정 풀)
- GENERAL 평균:  0.00개 / 5 (0.0%)  (NEW+WEAK 풍부 시 억제)
- MASTERED 평균: 0.00개 / 5 (0.0%)  (일반 5문항 세션 노출 완전 배제)
- 최근 10문항 중복률: 0.0000% (쿨다운 완전 배제)
======================================================
```

### 시나리오별 검증 결과
1. **Scenario A (NEW 300개, WEAK 10개, DUE 10개, MASTERED 100개)**:
   - NEW 문항이 정확히 3개(60%) 이상 배정되고, MASTERED 문항은 0개 섞임으로 완전 차단 확인.
2. **Scenario B (NEW 3개, WEAK 47개, DUE 50개)**:
   - 잔여 NEW 3개를 전량 우선 소진한 후, 나머지 2개 슬롯을 WEAK/DUE에서 정확히 선별 충원 확인.
3. **Scenario C (NEW 0개, WEAK 47개, DUE 50개)**:
   - NEW가 0개일 때 WEAK와 DUE가 최우선 배정되어 5개 슬롯 전량을 채움 (GENERAL/MASTERED 배제).
4. **Scenario D (최근 10문항 존재 시)**:
   - 직전 10문항 쿨다운이 100% 작동하여 0건의 중복 출현 달성.

## 3. 채점 엔진 및 기호 Normalization 전수 점검

### 3.1 `->` 기호 및 특수문자 회귀 검증
- **문제 현상**: 기존 `normalizeAnswer`의 특수문자 일괄 제거로 인해 `->`, `&`, `*`, `.` 등이 `""`로 변환되어 오답 처리됨.
- **해결 조치**:
  1. `isCodeOutputQuestion` 선행 판정으로 코드 트레이스의 토큰 경계 및 대소문자 보호.
  2. 순수 기호/연산자 패턴(`/^[->&*+=<!?:;~^%|/[\]()#.]+$/`) 도입으로 기호 원형 보존.
  3. `arrowNorm`을 통해 `->`, `→`, `⇒`를 유연하게 동등 표준화.
  4. `SYNONYM_GROUPS`에 연산자 명칭 동의어 보강.

### 3.2 13대 주요 연산자 기호 전수 점검 결과

```text
[검증 통과 매트릭스]
- ->   (화살표 연산자):             PASS (submitted -> expected ->)
- →    (유니코드 화살표):            PASS (submitted → expected ->)
- ⇒    (유니코드 이중 화살표):        PASS (submitted ⇒ expected ->)
- *    (포인터/곱셈 연산자):         PASS (submitted * expected *)
- &    (주소/비트AND 연산자):        PASS (submitted & expected &)
- ++   (증가 연산자):               PASS (submitted ++ expected ++)
- --   (감소 연산자):               PASS (submitted -- expected --)
- ==   (동등 비교 연산자):           PASS (submitted == expected ==)
- !=   (부등 비교 연산자):           PASS (submitted != expected !=)
- >=   (이상 비교 연산자):           PASS (submitted >= expected >=)
- <=   (이하 비교 연산자):           PASS (submitted <= expected <=)
- .    (구조체 멤버 접근 연산자):     PASS (submitted . expected .)
- ::   (C++ 범위 지정 연산자):        PASS (submitted :: expected ::)
```

### 3.3 회귀 방지 (Non-Regression) 보장
- `*` vs `&`: **오답 거부 (REJECT - PASS)**
- `==` vs `!=`: **오답 거부 (REJECT - PASS)**
- `2NF` vs `3NF`: **오답 거부 (REJECT - PASS)**
- `제2정규형` vs `제3정규형`: **오답 거부 (REJECT - PASS)**
- 코드 출력형 `1 23` vs `12 3`: **오답 거부 (토큰 경계 보존 - PASS)**
- 코드 출력형 `ABC` vs `abc`: **오답 거부 (대소문자 보존 - PASS)**

### 3.4 실제 문제은행 수록 문항 대조

## 4. AI Tutor 독립 검증 및 격리 (AIVerifier)

### 4.1 기본 호출 시 독립 검증 구조
사용자가 별도의 `⚖️ 검증` 버튼을 누르지 않더라도, **AI Tutor의 모든 기본 해설 요청 프롬프트(`buildTutorPrompt`)에 [독립 정답 검증 및 채점 안전 절대 원칙]이 강제 주입**됩니다:
1. **저장 정답 및 기존 해설 맹신 금지**: 저장된 정답과 기존 해설을 진실로 신뢰하지 않고 단순 검증 대상 데이터로 취급.
2. **지문/코드 독립 분석 선행**: AI 자신의 전문 지식으로 지문과 코드를 직접 풀어 **독립 정답(`independentAnswer`)을 먼저 도출**.
3. **저장 정답과의 대조 및 판정**:

```
[지문 / 코드 / 단서 조건] ──▶ AI 독립 정답 도출
                                    │
                  ┌─────────────────┴─────────────────┐
                  ▼                                   ▼
        [저장 정답과 일치]                   [저장 정답과 불일치]
                  │                                   │
        ┌─────────┴─────────┐                         ▼
        ▼                   ▼                QUESTION_SUSPECT
  [사용자 정답]       [사용자 오답]           - 기존 해설 노출 차단
   USER_CORRECT         USER_WRONG           - 채점 재검토 안내문 전환
  - 정답 인정 안내     - 일반 오답 해설       - AttemptRepository 격리
```

### 4.2 오답 데이터 격리 (Quarantine) 정책
- `QUESTION_SUSPECT` 또는 `USER_CORRECT` 감지 시:
  - `AttemptRepository.markAttemptSuspect(questionId, reason)`가 즉시 호출되어 해당 풀이 이력을 `isSuspect: true`로 마킹.
  - `AttemptRepository.getWrongQuestionSummaries`에서 `if (att.isSuspect) continue;`로 처리되어 **오답 횟수 증가 금지, weak score 증가 금지, 자동 복습 우선순위 배제**가 완벽히 보장됨.
  - 메모리 내 `VERIFICATION_LOGS`에 감사 기록으로 안전 보관.

### 4.3 불확실 및 API 장애 대응
- `VERIFICATION_UNCERTAIN`: 단서가 부족하거나 판단이 모호한 경우 단정 짓지 않고 추가 확인 안내문 제공.
- **API 네트워크/서버 오류 (429, 503, Timeout 등)**: AI가 정밀 검증을 완료했다고 허위 표시하지 않고, 기본 채점을 유지한 채 "AI 튜터 서버 연결이 원활하지 않아 정밀 검증이 완료되지 못했습니다"라는 안내문으로 안전 처리.

## 5. 실제 문제 End-to-End 검증 사례

### Case 1. 정상 문제 검증 (`EXP_PR_007`)
- **지문**: C언어 구조체 포인터 변수를 통해 해당 구조체의 멤버 변수에 접근할 때 사용하는 화살표 모양의 멤버 접근 연산자 기호
- **사용자 제출**: `->`
- **로컬 채점**: `CORRECT`
- **AI 검증 결과**: `USER_CORRECT` (로컬 채점과 완전 일치)
- **해설 표시**: 기존 공식 해설 정상 표시 (왜곡 없음)

### Case 2. 오류 의심 및 오답 격리 검증 (`EXP_SUSPECT_01`)
- **지문**: 시간의 흐름에 따른 객체들의 동적 행위를 표현하는 럼바우 모델링 기법
- **수험생 제출**: `동적 모델링` (실제 정답)
- **저장 정답**: `잘못저장된답` (모의 오류 주입)
- **로컬 채점**: `WRONG`
- **AI 독립 검증 결과**: `QUESTION_SUSPECT` (지문 분석 결과 "동적 모델링"이 독립 정답이며 저장 정답에 모순 감지)
- **UI 해설 표시**:
  > `⚠️ [채점 재검토 안내]`
  > 이 문제는 문제 지문 또는 제시된 코드와 저장된 정답 간에 모순이 감지되어 재검토 대상으로 분류되었습니다.
  > - AI 독립 분석 결과: "동적 모델링"
  > - 등록된 정답: "잘못저장된답"
  > 잘못된 지식 습득 방지를 위해 기존 해설 표시가 일시 제한되며 수험생 오답률에 반영되지 않습니다.
- **오답 집계 격리 결과**: `AttemptRepository.getWrongQuestionSummaries` 조회 결과 오답 목록에서 100% 배제 확인.
